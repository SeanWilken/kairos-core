# v1 Compatibility Notes

This document records compatibility guarantees for the MyAI Core v1 API surface.

## Scope

These notes apply to all `v1` HTTP endpoints under `/v1/*`.

## Stable Envelope Contract

All v1 responses use the same top-level envelope keys:

- `meta`
- `data`
- `error`

Compatibility guarantees:

- top-level envelope keys are stable in v1
- `data` is `null` on error responses
- `error` is `null` on success responses

## Stable Meta Contract

`meta` is present on both success and error responses.

Required fields:

- `service`
- `version`
- `spec_version`
- `environment`
- `timestamp`
- `correlation_id`

Compatibility guarantees:

- `meta.spec_version` is always `"v1"` for v1 endpoints
- `meta.correlation_id` is always present

## Correlation ID Behavior

Header: `X-Correlation-ID`

Behavior guarantees:

- if a client supplies `X-Correlation-ID`, the API echoes that value in the response header
- if not supplied, the API generates a correlation ID
- `meta.correlation_id` matches the response `X-Correlation-ID` value

## Protected Scope Requirements (v1 baseline)

Protected endpoints (for example `/v1/protected/ping`) require request scope headers:

- `X-Tenant-ID`
- `X-Org-ID`

If required scope is missing:

- HTTP status: `403`
- top-level error code: `ACCESS_DENIED`
- machine-readable denial reason is returned in `error.details.reason_code`

Current reason codes:

- `TENANT_CONTEXT_MISSING`
- `ORG_CONTEXT_MISSING`

## Error Code Catalog (v1)

Stable top-level error codes currently include:

- `NOT_FOUND`
- `ACCESS_DENIED`
- `UNAUTHORIZED`
- `VALIDATION_ERROR`
- `INTERNAL_SERVER_ERROR`
- `HTTP_ERROR` (fallback for unmapped statuses)

## Evolution Rules for v1

Allowed in v1:

- additive response fields
- additive metadata in `error.details`
- new endpoints under `/v1/*` that preserve the v1 envelope/meta rules

Not allowed in v1 without version change:

- removing or renaming envelope keys
- removing required `meta` fields
- changing existing field types
- changing stable error code semantics in a breaking way

Breaking compatibility changes require a new versioned API surface.
